Root-cause diagnosis (verified in code)

1. Stories are linear — the engine has no branching machinery.
- seed_scenarios.dart gives each scenario a single fixed opening_scene string. prompt_builder.dart:352-360 tells the model "Begin the story here" and "Only characters from the cast section may appear". That's a script, not a branching system.
- opening_suggestions (10 chips per scenario) are never consumed by the engine — prompt_builder.dart:253 buildAction() only handles isContinue / player text / fallback. Suggested actions are UI-only.
- There's no plot-state tracking. world_state.dart tracks location/time/weather/facts/flags — but nothing like act, chapter, quest_branch, or story_state. So the model has no signal about where it is in an arc, and nothing compels divergence.
- prompt_builder.dart:24 rule #4 says "structured state > pinned memories > recent scene > world rules > scenario text" — but when state is empty (which it is for most of a new story), the scenario text wins by default, pulling the narrative back onto the rails.

2. Only 10 scenarios, and 9 of 10 have no cover art.
- assets/covers/ contains only scenario1.jpg. Scenarios 2–10 reference assets/covers/scenario2.jpg … scenario10.jpg in their cover_art field, but those files do not exist → Image.asset errors → falls back to GenreBanner (a gradient). So 90% of the Discover grid is generic colored boxes.
- The library StoryTile (widgets.dart:272) shows a CircleAvatar with the first letter of the title — it never renders the story's cover, so custom-created stories' images never appear in the library either. That's your "image doesn't show" bug.

3. Characters fade into the background — three concrete leaks.
- prompt_builder.dart:168 buildNpcs({int limit = 8}) — caps the cast at 8. Arcanum Academy has 16 NPCs; the Isekai scenario has 21. Half the cast is never even sent to the model.
- story_engine.dart:527 applyAnalysisToWorld only updates NPCs the model explicitly reports in npc_updates. If the model doesn't name an NPC for 5 turns, that NPC's emotionalState/location/relationship all freeze. There's no background-simulation step — NPCs never interact with each other off-screen, so there's no "NPC economy" to draw from.
- memory.dart pins max 15 facts and summarizes every ~16 turns. NPC relationship arcs are not memories — they're mutable columns. Nothing re-prompts the model about a cooling relationship, so drift is invisible until it's a total freeze.

4. "Create your character first" confusion (verified).
- create_story_page.dart:351 labels the 1-on-1 NPC section as "YOUR CHARACTER" (Mira the cafe owner). Then _createAndStart at line 148 pops _PlayerCharacterSheet titled "Your character". Two different things both called "your character." The user thinks the NPC is their avatar.

5. Genre gap. 10 scenarios, all fantasy/isekai/sci-fi/political. No horror, no zombie/post-apoc, no noir, no romance-only, no historical, no slice-of-life cozy.

Phase 1 — Branching engine (the core, ~1 week)
This is the single change that makes the app feel like ISEKAI ZERO.

5. Add story_state to the world model (world_state.dart). New top-level keys:
- act (int): current story act
- branch (String?): active branch id
- arc_progress (0..1): where we are in the current arc
- pending_forks: list of unresolved fork points the player could still take
- tone (String): current mood — grim / cozy / tense / lighthearted

6. Fork definitions on scenarios. Add a forks list to Scenario:
forks: [
  { id: 'ally', trigger: 'gain X trust', leads_to: 'act2_allied' },
  { id: 'rival', trigger: 'betray / lose trust', leads_to: 'act2_hostile' },
]
Plus per-fork opening_scene variants. The opening prompt then becomes "Begin in branch X" instead of one fixed script.

7. Divergence scoring. After each turn, the analysis step (analysis.dart) gains a branch_delta field. applyAnalysisToWorld updates branch when a fork triggers. The prompt then includes CURRENT BRANCH: X so the model self-consistently stays on the rails it chose.

8. "What if" replays. A new UI affordance in the player: long-press a message → "What if I'd done X?" → clones the story state, runs a 1–2 turn simulation, shows a preview, lets you commit or discard. Reuses rewindTo machinery.
Phase 2 — Cast persistence (the "characters fade" fix, ~4 days)

9. Per-NPC memory table. Add npc_memories (npc_id, fact, importance, created_seq) — separate from global memories. buildNpcs injects each NPC's last 3–4 personal memories into their card so the model knows what they remember about the player.

10. Background simulation step. New engine method simulateOffScreen(npcs, state) called once per turn before the prompt is built. It's a cheap LLM call (small model / low tokens) that answers: "While the player wasn't looking, what did NPCs A, B, C do? Update their moods/locations/relationships." This creates the NPC economy so characters don't freeze. Feed the result into buildNpcs as Current status: lines.

11. Relationship drift. In applyAnalysisToWorld, when an NPC isn't mentioned in npc_updates for N turns, decay their relationshipValue by 1–2 and set emotionalState to a default. Make drift visible in the Companions sheet so the player sees it cooling.

12. Un-cap NPC injection fully — drop the take(limit) and instead summarize overflow into a "Also present (background): ..." line.
